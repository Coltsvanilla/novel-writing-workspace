# 物語ビューア

story-creator が `stories/` に作る進捗と成果物を、ブラウザで確認・レビューするローカルアプリです。読み取り専用で、ファイルは変更しません。

## 使い方

1. `viewer/start.cmd` をダブルクリックする（初回のみライブラリを取得します）。
2. ブラウザが開きます。終了するときは黒い画面で `Ctrl+C` を押すか、ウィンドウを閉じます。

必要なもの：Node.js 20 以上。アドレスは既定で http://localhost:8765/ です（使用中なら次の番号へ移ります）。`start.cmd --port=9000` や `--stories=<フォルダ>` で変えられます。

## 設計の要点

- **真実の源は `stories/` のMarkdown。** ファイルが変わるとブラウザが自動で更新されます（Claude が書いている最中の進み具合も見えます）。
- **レビューは差分で。** story-creator は承認された状態だけをコミットします。そのため、作業ツリーと直近コミットの差が「前回承認からの未承認の変更」になり、成果物の画面で「差分」として見られます。
- **相関図は表から描きます。** `04_relationships.md` の表が正で、章スライダーで関係の移り変わりを追えます。

## 長編モード（部 → 章 → 節）

物語フォルダに `02_part-outline.md` または `06_chapter-plots/part01/` のような部ごとのフォルダがあると、長編モードとして読みます。短編の物語はこれまでどおりです。

- **章の表記は「第P部 第N章」**（章番号は部の中で数える）。ファイルは `06_chapter-plots/part01/ch03.md`、`07_chapters/part01/ch03.md`。
- **通し番号で動かす。** 画面の並び・相関図のスライダー・人物の登場表などは、部→章の順に1から振った通し番号で扱い、表示だけ「第2部 第3章」にします（`lib/chapters.js`）。
- **表の「章」列の書き方：** 「第2部 第3章」、範囲「第2部 第1〜4章」、列挙「第2部 第1・3章」、部全体「第2部」、複数の部「第1部〜第3部」。
- **部の進捗：** `progress.md` の「部の進捗」表（列：部・タイトル・章構成・設定更新／起承転結／本文／中間レビュー）と、「第P部 章ごとの状況」の表を読みます。概要画面に、部ごとの工程と章の一覧が出ます。
- **その他の成果物：** `story-state.md`（物語の現在地）、`02_chapter-outlines/partNN.md`（部ごとの章構成）、`08_review/partNN.md`（部の中間レビュー）が、左の一覧に出ます。
- **完成稿：** `## 第N部` の中に `### 第M章` を入れた形なら、目次が部→章の入れ子になります。

## 構成

| パス | 責務 |
|---|---|
| `server.js` | 読み取り専用のAPIと静的配信、ファイル変更の通知（SSE）。`localhost` からのアクセスだけ応答する |
| `lib/md.js` | Markdown の表・見出し・箇条書きの読み取り |
| `lib/story.js` | 物語フォルダ → 画面が読むモデル（フェーズ、部、章、人物、関係、重要な物、レビュー） |
| `lib/chapters.js` | 章の参照（「第2部 第3章」など）を通し番号に直す。表示名を引く（サーバーと画面で共有） |
| `lib/relations.js` | 「第N章の時点」の相関図を決める関数（サーバーと画面で共有） |
| `lib/git.js` | 承認履歴と、未承認の変更・差分 |
| `public/` | 画面（素のESモジュール。外部への通信なし） |
| `test/` | `npm test`。実物の物語とサンプル（`test/fixtures/`）で解析を確認する |
