# 長編モード（部 → 章 → 節）

約10万字を超える物語（目安：50万字級）を作るときの手順。短編・中編（約10万字まで）は、`SKILL.md` の通常の手順のままでよい。このファイルは、**通常の手順との差分**を書く。ここに書かれていない点（承認ゲートの進め方、上流の成果物の直し方、品質の基本姿勢）は、`SKILL.md` と `references/phase-guides.md` のとおり。

## なぜ手順を変えるのか

通常の手順は、全章の構成・人物・起承転結を先に固め、1章ずつ承認する。50万字・50章になると、次の問題が出る。

- **先に決めすぎると崩れる。** 第5部の細部を最初に決めても、第2部を書くうちに人物や関係が育ち、設計が古くなる。
- **承認が多すぎる。** 50章を1章ずつ承認すると、確認の負担が大きく、流れが細切れになる。
- **前提が失われる。** 数十章前の設定、張った伏線、人物の現在の状態が、長い作業のあいだに抜け落ちて、矛盾の原因になる。

そこで、**全体は骨格だけ先に決め、詳細は「部」ごとに、その部に入る直前に決める。承認は部と章のまとまりで取る。物語の最新の状態は `story-state.md` に集めて、書く前に必ず読む。**

## いつ長編モードにするか

- 補足で長さの希望が約10万字を超える、または「長編」と指定されたとき。
- 迷ったら、規模（部の数・総字数）をユーザーに確認して決める。
- 長編モードにしたら、`progress.md` の「インプット」に「**モード：** 長編」と、想定の規模（部の数、各部の章数、総字数）を記録する。

## 構造と字数の目安

| 階層 | 単位 | 字数の目安 | 数の目安（50万字の場合） |
|---|---|---|---|
| 部 | 物語の大きな区切り（文庫1冊分に相当） | 約10万字 | 5部 |
| 章 | 一つのエピソード。章の中に起承転結を持つ | 約1万字 | 各部10章前後（計約50章） |
| 節 | 一つの場面（場所・時間・視点が変わる単位） | 約2,500字 | 各章4節（計約200節） |

- **1章＝4節＝起承転結。** 節1＝起、節2＝承、節3＝転、節4＝結。通常の手順のフェーズ6（章ごとの起承転結）が、そのまま使える。
- 字数や節の数は目安。ユーザーと相談して `progress.md` の「執筆方針」に決めた値を書く。章によって節が3つ、5つになるのは構わないが、**その章の起承転結ファイルに明記する**。
- 部の数が決まっていなければ、フェーズ1〜2aで、想定の巻数・形態（文庫何冊分か、連載か）をユーザーに確認して決める。

## 章番号と参照の書き方

- **章番号は部の中で数える。** 「第1部 第3章」の形。部が変わると、第1章に戻る。
- **表や文中で章を指すときは、必ず次の書式にする。** 閲覧ツール（`viewer/`）が、この書式から章の並びを読み取るため。

| 指したいもの | 書き方 |
|---|---|
| 1つの章 | `第2部 第3章` |
| 範囲 | `第2部 第1〜4章` |
| 列挙 | `第2部 第1・3章` |
| 部全体 | `第2部` |
| 複数の部 | `第1部〜第3部` |

- 対象は、`03_characters.md` の「主に登場する章」、`04_relationships.md` の「章」列と「初登場の章」「退場の章」、`05_key-items.md` の「章」列、各ファイルの見出しやタイトルなど。
- 人物の登場の「本編と言及」の分け方は、通常と同じ（例：`第1部 第1〜5章（第2部 第1章は回想）`）。

## 手順の全体像（部のループ）

**物語全体で一度だけ行うこと** → **部ごとに繰り返すこと** → **最後に一度だけ行うこと**、の3段階になる。

### 物語全体で一度だけ（最初）

| ゲート | 内容 | 成果物 | コミットメッセージ |
|---|---|---|---|
| G1 | フェーズ1 アイデア出し（部ごとの方向性も含める） | `01_ideas.md` | `フェーズ1承認：アイデア出し` |
| G2 | フェーズ2a 部の骨格 | `02_part-outline.md` | `フェーズ2a承認：部の骨格` |
| G3 | フェーズ3 登場人物（初期：主要人物と世界設定） | `03_characters.md` | `フェーズ3承認：登場人物の整理（初期）` |
| G4 | フェーズ4 相関関係図（初期） | `04_relationships.md` | `フェーズ4承認：相関関係図（初期）` |
| G5 | フェーズ5 重要な物（初期） | `05_key-items.md` | `フェーズ5承認：重要な物の整理（初期）` |

G3〜G5を終えたあと、`story-state.md` を作る（最初の版。部のあらすじ要約はまだ空でよい）。

### 部ごとに繰り返す（第1部、第2部、…）

| ゲート | 内容 | 成果物 | コミットメッセージ |
|---|---|---|---|
| P1 | **部の準備**：その部の章構成（フェーズ2b）と、人物・相関・物の更新差分（フェーズ3〜5） | `02_chapter-outlines/partNN.md`、`03`〜`05` の更新 | `第N部 準備承認：章構成・設定更新` |
| P2 | **部の起承転結**（フェーズ6）：その部の全章分 | `06_chapter-plots/partNN/` | `第N部 フェーズ6承認：章ごとの起承転結` |
| P3 | **本文**（フェーズ7）：下記の粒度で承認 | `07_chapters/partNN/` | 下記 |
| P4 | **部の中間レビュー**＋`story-state.md` の更新 | `08_review/partNN.md`、`story-state.md` | `第N部 中間レビュー承認` |

P3（本文）の承認の粒度：

- **その部の最初の2章は、1章ずつ承認する。** 部の序盤の文体・テンポ・人物の声を確かめるため。最初の部（第1部）では、特に慎重に。
  - コミットメッセージ：`第N部 フェーズ7承認：第M章「<章タイトル>」`
- **それ以降は、3章ごとにまとめて承認する。** 章数が3で割り切れないときは、最後の1〜2章をまとめて承認する。
  - コミットメッセージ：`第N部 フェーズ7承認：第A〜B章`
- ユーザーが「1章ずつ見たい」と言えば、1章ずつに戻す。逆に、ユーザーが「もっとまとめて」と言えば、まとめる章数を増やしてよい。

**前の部のP4が承認されるまで、次の部のP1に入らない。** 先の部の細部を早く決めすぎると、前の部を書く過程で育った設定と食い違うため。

### 最後に一度だけ

| ゲート | 内容 | 成果物 | コミットメッセージ |
|---|---|---|---|
| G8 | フェーズ8 全体レビュー → 完成稿 | `08_review.md`、`09_manuscript.md` | `フェーズ8承認：全体レビュー反映・完成稿作成` |

### `progress.md` の「フェーズ進捗」表（全体）の読み替え

| フェーズ | 「承認済み」にする時期 |
|---|---|
| 1 | G1の承認時 |
| 2 | G2（部の骨格）の承認時。以降、部ごとの章構成はP1で扱う |
| 3〜5 | G3〜G5（初期）の承認時。以降の更新はP1で扱う |
| 6・7 | **全部のP2・P3が承認されたとき**。それまでは「作成中」 |
| 8 | G8の承認時 |

部ごとの細かい状態は、`progress.md` の「部の進捗」表と、「第N部 章ごとの状況」表で管理する（ビューアがここを読む）。

## フェーズ別の手順

### フェーズ1：アイデア出し

通常のフェーズ1（`phase-guides.md`）に加えて、次を確定させる。

- **物語全体の規模**：部の数、各部の章数、総字数の目安、形態（文庫何冊分か、連載か）。
- **部ごとの方向性**：各部が物語全体の中で果たす役割（例：第1部は日常と揺らぎ、第2部は旅立ち）。採用案の「確定したあらすじ」を、部ごとに2〜4行で分けて書く。

### フェーズ2a：部の骨格（`02_part-outline.md`）

- 部ごとに、タイトル、概要、物語全体での役割、部の開始時点の状態、部の終了時点の状態を書く。
- 「**部の終了時点の状態**」は、次の部の開始時点につながるように書く（章構成のときと同じ理由）。
- **部をまたぐ大きな流れ**（主人公の変化、最大の謎、対立の推移）を、「部をまたぐ流れ」の表に書く。細かい伏線はまだ決めなくてよい。
- 第1部は、のちに詳細を決めるので、骨格では粗くてよい。ただし、**物語全体の結末への到達点**は、最終部の「部の終了時点の状態」に必ず書く。

### フェーズ2b：部の章構成（`02_chapter-outlines/partNN.md`）

- **その部に入る直前（P1）で作る。** 前の部のP4が承認され、`story-state.md` が最新になってから。
- 通常のフェーズ2と同じ項目（章のタイトル、概要、役割、開始・終了時点の状態）。章の番号は部の中で第1章から。
- その部の最初の章は、前の部の終わり（`story-state.md` の「現在地」）から始まる。最終章は「部の終了時点の状態」で終わる。

### フェーズ3〜5：初期版と、部ごとの更新

- **初期版（G3〜G5）**：物語の世界、主要人物（主人公、主な味方と敵対者）、最初の部で必要な関係と、重要な物。第5部にしか出ない脇役まで先に作らない。
- **部ごとの更新（P1）**：その部の章構成を決めたあとで、次を行い、**差分だけ**をユーザーに提示する。
  - その部で新しく登場する人物・重要な物を追加する（`03`〜`05`）。
  - 前の部で変わった人物の状態・関係を、追加情報や関係の変化表に反映する。
  - 「章」の表記は、必ず `第N部 第M章` の形。
- 既存の内容を**変更**するときは、通常の「上流の成果物を直す必要が出たとき」と同じ手順で、ユーザーの了承を得る。追加（新しい人物・物など）は、了承なしで追記してよいが、P1の差分に必ず含める。

### フェーズ6：部の起承転結（`06_chapter-plots/partNN/chNN.md`）

- **部単位で作成し、部全体として承認する（P2）。** 章どうしのつながりを一覧して確認してもらうため。
- 1章＝4節。**節1＝起、節2＝承、節3＝転、節4＝結**。節ごとに、時間・場所、視点人物、登場人物、出来事、感情の変化を書く。
- 整合性チェックは、通常（相関図・アイテム表）に加えて、次を確認する。
  - `story-state.md` の「現在地」「人物の現在の状態」と、その部の第1章の開始が合っているか。
  - 部の最終章が、`02_part-outline.md` の「部の終了時点の状態」に到達しているか。
  - **未回収の伏線**の回収予定が、どの章に置かれているか。
- ユーザーへの提示は、部の全章を、各章1〜2行にまとめた一覧で示す。

### フェーズ7：本文（`07_chapters/partNN/chNN.md`）

- **章を順番に1つずつ書く。** 承認は、上記P3の粒度で取る。
- **各章を書く前に、必ず次を読む**（長期作業で前提を失わないため）。
  1. `story-state.md`（現在地、人物の現在の状態、未回収の伏線）
  2. その章の起承転結（`06_chapter-plots/partNN/chNN.md`）
  3. 直前の章の末尾（最後の1,000字程度）
  4. その章に出る人物・物の項（`03`〜`05`）
- 節は、本文の中で「＊」の行で区切る（節の見出しは付けない）。章の最初の見出しは `# 第N部 第M章「タイトル」`。
- 本文で新しく決まった設定（人物の癖、地名、過去の出来事など）は、章ファイルの「肉付けメモ」に書き、承認のたびに、`03`〜`05`、`story-state.md` に反映する（フェーズ名を添える）。
- 台詞の書き方は、通常のフェーズ7（`phase-guides.md`）のとおり。

### フェーズ8：中間レビューと全体レビュー

- **部の中間レビュー（P4）**：その部の全章を通して読み、`08_review/partNN.md` に書く。観点は、通常の全体レビューの観点に、次を加える。
  - 部の終了時点の状態に到達しているか。
  - 次の部につながる材料（未解決の問い、人物の状態）が、`story-state.md` に書かれているか。
  - その部で張った伏線、回収した伏線、持ち越す伏線。
  - 章どうしのテンポ（部の中で、盛り上がりが偏っていないか）。
- 指摘は、通常のレビューと同様に、ユーザーが選んだものだけ反映する。反映後の確認と承認を得てから、`story-state.md` を更新して、コミットする。
- **全体レビュー（G8）**：全部を通して読むのは分量が大きいので、次に絞る。
  1. 各部の中間レビューで「持ち越し」とされた指摘の確認。
  2. 部と部のつながり、物語全体の結末への到達。
  3. 人物の変化の一貫性（主要人物は、全部を通して）。
  4. 未回収の伏線の最終確認（`story-state.md` の表がすべて「回収済み」または「意図的に残す」か）。
  5. 文体と表記（固有名詞の表記ゆれ、章ごとの読点の量の偏りなどを、検索や集計で機械的に確かめる）。

## story-state.md（物語の現在地）の運用

長編の肝になる、**最新の状態の集約ファイル**。テンプレート：`assets/templates/story-state.md`。

| 節 | 中身 |
|---|---|
| 現在地 | どの部の第何章まで承認済みか。物語内の現在の日付・場所・状況 |
| 部ごとのあらすじ要約 | 承認済みの各部を、5〜10行で要約（結末の状態まで） |
| 人物の現在の状態 | 主要人物ごとの、居場所・状況・心情・持ち物・最後に登場した章 |
| 未回収の伏線 | 伏線、張った章、回収予定の章、状態（未回収／回収済み／意図的に残す） |
| 時系列メモ | 物語内の日付・経過日数。季節、年齢の変化など |
| 確定した設定の変更点 | 後から変わった設定の記録（何を、どう変えたか、いつ） |

運用のルール：

- **P4（部の中間レビュー）の承認時に、必ず更新する。** 更新しないまま次の部に入らない。
- **P3の承認時にも、軽く更新する**（現在地、人物の現在の状態、新しく張った伏線）。
- **フェーズ7で章を書く前に、必ず読む。**
- 内容は**簡潔**に。詳細は、元の成果物（`03`〜`05`、各章）が持つ。このファイルは「いま何を覚えておくべきか」だけを持つ。
- 食い違いを見つけたら、`story-state.md` ではなく、元の成果物（承認済みの本文・設定）を正とし、`story-state.md` を直す。ただし、元の成果物の側が間違っている場合は、ユーザーに報告して一緒に直す。

## 長期執筆の注意

- **部の骨格を黙って変えない。** 物語が育って骨格を変えたくなったら、理由と影響範囲（以降の部、`story-state.md`）をユーザーに伝え、了承を得てから直す。変更は `progress.md` の「変更履歴」に記録する。
- **長い作業で会話が切れても再開できるようにする。** 再開時は、`progress.md` の「部の進捗」と「章ごとの状況」、`story-state.md` を読み、承認済みの最後の位置の次から始める。
- **文体のぶれに注意。** 第1部で確定した文体・台詞の声は、後の部でも守る。部をまたぐと、章を追うごとに読点が増える・説明が増えるなどの偏りが出やすい。各部の中間レビューで、章ごとの読点の量などを機械的に数えて確かめる。
- **コミットの単位。** 通常と同じく、ユーザーが承認した状態だけをコミットする。部が完了（P4承認）したら、親リポジトリのサブモジュールのポインタを更新するかどうか、ユーザーに提案する（`references/git-workflow.md`）。
- **閲覧ツール（`viewer/`）。** 長編モードの物語を、部ごとの進捗、章の一覧、相関図のスライダー、完成稿の目次として表示できる。承認前の確認に使うよう、最初の提示のときに一度だけ案内する。

## 完成稿の形式

`09_manuscript.md` は、次の形で結合する。

```
# 物語名

## 第1部「部のタイトル」

### 第1章「章のタイトル」
```
