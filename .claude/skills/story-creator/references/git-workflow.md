# Git運用（成果物リポジトリ）

## 構成

- **スキルのリポジトリ（親）：** 作業ディレクトリ直下。スキル本体（`.claude/skills/story-creator/`）を管理する。
- **成果物のリポジトリ（子）：** 物語ごとに1つ。`stories/<物語名>/` が独立したGitリポジトリで、親からは**サブモジュール**として参照する。

成果物を親に直接コミットしないのは、スキルの改善履歴と物語の執筆履歴を混ぜないため、そして物語ごとに公開・共有・削除できるようにするため。

```
<作業ディレクトリ>/            ← 親リポジトリ（スキルを管理）
├── .claude/skills/story-creator/
├── .gitmodules                ← サブモジュールの登録情報
└── stories/
    ├── <物語A>/               ← 子リポジトリ（サブモジュール）
    └── <物語B>/               ← 子リポジトリ（サブモジュール）
```

## 前提の確認

`git --version` が実行できることを最初に確認する。実行できない場合は、Gitがインストールされていないことをユーザーに伝え、物語作成そのものは続けつつ（ファイルは普通に作る）、コミットとサブモジュール登録は行わない。インストールはユーザーに確認してから。

## 新しい物語を始めるとき

物語名が決まり、`stories/<物語名>/progress.md` を作ったら、次の順に行う。PowerShellでは `&&` が使えないので、コマンドは1行ずつ実行するか `;` でつなぐ。

1. **リモートURLを尋ねる。** ユーザーが事前に空のリポジトリを作っておく前提。URLがまだなければ、あとで登録できるので「後で」でよい（手順4と5を飛ばし、手順6でその旨を伝える）。リポジトリ自体を代わりに作ることはしない。
2. **子リポジトリを初期化して最初のコミットを作る。**
   ```powershell
   git -C "stories/<物語名>" init -b main
   git -C "stories/<物語名>" add -A
   git -C "stories/<物語名>" commit -m "物語リポジトリを作成"
   ```
3. （手順2のあと）コミット時にユーザー名・メールが未設定でエラーになったら、勝手に設定せず、ユーザーに設定をお願いする。
4. **リモートを登録する**（URLがある場合）。
   ```powershell
   git -C "stories/<物語名>" remote add origin <URL>
   ```
5. **親にサブモジュールとして登録する**（URLがある場合）。作成済みの子リポジトリがすでにそこにある場合、`git submodule add` はそれを取り込む。
   ```powershell
   git submodule add <URL> "stories/<物語名>"
   git add .gitmodules "stories/<物語名>"
   git commit -m "物語「<物語名>」をサブモジュールとして追加"
   ```
6. `git submodule status` で登録を確認する。URLがなくて登録を飛ばした場合は、「あとで `git submodule add <URL> stories/<物語名>` で登録できる」と伝える。

**pushは行わない。** リモートへの送信はユーザーが判断する（公開・共有にあたるため）。

## フェーズ承認ごとのコミット

ユーザーが承認し、`progress.md` を「承認済み」に更新したあとに、子リポジトリでコミットする。

```powershell
git -C "stories/<物語名>" add -A
git -C "stories/<物語名>" commit -m "<メッセージ>"
```

| タイミング | コミットメッセージ |
|---|---|
| フェーズ1〜5の承認 | `フェーズN承認：<フェーズ名>`（例：`フェーズ3承認：登場人物の整理`） |
| フェーズ6の承認 | `フェーズ6承認：章ごとの起承転結` |
| フェーズ7の各章の承認 | `フェーズ7承認：第N章「<章タイトル>」` |
| フェーズ8の承認（レビュー反映・完成稿の作成後） | `フェーズ8承認：全体レビュー反映・完成稿作成` |
| 承認済みの上流成果物の修正 | `修正：<ファイル名> <内容の要約>`（承認ゲートのコミットとは分けて、修正だけの単独コミットにする） |

- **承認前の修正中はコミットしない。** コミットは「ユーザーが承認した状態」だけを積む。これで履歴をたどれば、各フェーズの承認時点にいつでも戻れる。
- 親リポジトリのサブモジュールのポインタ（子の最新コミット）は、承認のたびには更新しない。親の履歴がスキルの変更ではなく執筆の進捗で埋まるため。ポインタの更新はユーザーが必要なときに行う。
- コミットに失敗したら、エラーをそのままユーザーに伝え、物語作成は止めずに続ける（ファイルは保存されている）。

## 再開時

親をクローンした直後など、`stories/<物語名>/` が空の場合は、サブモジュールが未取得。`git submodule update --init "stories/<物語名>"` で取得してから `progress.md` を読む。
